# 新增站点 / 新增模型清单

加一个新站点（渠道）或者给已有站点加模型时，照着这份清单一项项打勾。站点信息现在分散在很多文件里，漏改一处就可能出问题，最危险的是两种：

- **用户看到供应商真名**：漏了 `account/mask.js`
- **扣了钱卡住没退款**：漏了 `account/task-sweeper.js` 或任务状态识别

`tests/channel-consistency.test.mjs` 会自动检查下面打了 🧪 的项。漏改时 `npm test` 会报错，并指出是哪个文件。没打 🧪 的项要自己对照检查。

> 下面用 `newsite` 代表新站点的 id，id 要用小写英文，所有地方都写同一个。

---

## 一、新增站点

### 1. 对接接口（新文件）

- [ ] 新建 `newsite-api.js`，照着 `grsai-api.js` / `runninghub-api.js` 的写法导出：
  - `NEWSITE_ORIGIN`（接口地址）、`NEWSITE_SITE_ID = "newsite"`、`NEWSITE_SITE_NAME`（管理员看到的简称）
  - 模型列表 `NEWSITE_SITE_MODELS` / `NEWSITE_IMAGE_MODELS` / `NEWSITE_TEXT_MODELS`
  - 生成请求 `newsiteImageRequestSpec`、价格 `newsiteImagePrice`、余额查询 `fetchNewsiteAccount`
- [ ] 给它写测试：`tests/newsite-*.test.mjs`，至少覆盖请求格式、价格、超时

### 2. 编号、顺序、备注（用户能看到的）

这几份内容是一样的，要**全部**改成相同的值：

- [ ] 🧪 `display-order.js`：`SITE_DISPLAY_ORDER`、`SITE_CHANNEL_LABELS`（"渠道 N"）、`SITE_CHANNEL_NOTES`
- [ ] 🧪 `account/channels.js`：`CHANNELS`（名称、充值链接、模型）和 `CHANNEL_LABELS`
- [ ] 🧪 `account/mask.js`：`CHANNEL_LABELS`
- [ ] 🧪 `admin.html`：`COLS`、`CHANNEL_NAME`
- [ ] 🧪 `canvas-price-table.js`：`order`、`names`（管理员和用户各一份）、`notes`、`providerClass`；还有 `site` 那串判断和 `advantages`（管理员看的备注）
- [ ] 🧪 `account-ui.js`：`SITE_SHORT`

### 3. 服务端：认地址、扣费、退款、隐藏真名

- [ ] 🧪 `account/relay.js`：`HOSTS` 加上新站点的域名。不加的话服务器会拒绝转发，提示"这个平台不支持余额生成"
- [ ] 🧪 `account/mask.js`：`NAME_PATTERNS` 加上新站点的名字和常见写法。不加的话，报错信息里会露出供应商名字
- [ ] 🧪 `account/task-sweeper.js`：`STATUS_REQUEST` 加上查询任务状态的接口。不加的话，用户关掉页面后卡住的任务不会被清理和退款
- [ ] `account/tasks.js`：确认 `taskOutcome` / `findTaskId` 能读懂新站点返回的任务状态和任务号。字段名不一样就要补，不然成功和失败都认不出来
- [ ] `account/channels.js`：`queryBalance` 加上新站点的余额查询
- [ ] 🧪 `account/alerts.js`：`wanted` 加上新站点（余额不足提醒）
- [ ] `account/catalog.js`：加一个 `newsiteRows()`，列出这个站点每个模型、每个分辨率的价格行；文字模型加到 `textRows()`
- [ ] `account-pricing.js`：`providerRequest` 的 `builders` 加上新站点（前端算价格用）
- [ ] 🧪 `deploy/seed-prices.mjs`：`plan` 加上新站点的初始售价

### 4. 前端：画布、余额、颜色

- [ ] 🧪 `index.html`：`balanceHost` 正则加上新域名（生成后刷新余额）
- [ ] 🧪 `account-ui.js`：`SITE_BY_HOST` 加上新域名
- [ ] 🧪 `theme.css` 加 `--lw-site-newsite`；🧪 `index.html` 加 `.canvas-site-menu-item[data-site="newsite"]`。颜色遵守审美规则，**不要用绿色当主色**
- [ ] 🧪 打包文件 `assets/index-B2KJ37fm.js`（最费事的一步）：
  - 开头 import 新的 `newsite-api.js`
  - 搜 `RUNNINGHUB_SITE_ID`、`provider==="runninghub"`，照每一处的样子给新站点加一份。目前大约 12 处，包括默认站点列表、站点识别、provider 判断那一串、站点颜色、生成调用
  - 用脚本做"只匹配一次"的精确替换；改完运行 `node --input-type=module --check < assets/index-B2KJ37fm.js`

### 5. 测试和版本号

- [ ] 🧪 `tests/channel-consistency.test.mjs`：`ORIGINS` 加上新站点的接口地址，最后一条断言加上 `NEWSITE_SITE_ID`
- [ ] 搜 `["tudou", "apimart", "grsai", "runninghub"]`，把其他测试里写死的渠道列表也更新
- [ ] 所有改过的前端文件，在引用它的地方换新的 `?v=`：
  - `index.html` 里打包文件有 **两处**（modulepreload 和 script），要一致
  - 打包文件开头 import 的 `display-order.js`、`account-pricing.js`、`newsite-api.js`
- [ ] `npm test` 全部通过

### 6. 本地验证（不能只跑测试）

- [ ] 启动本地预览（命令见 `HANDOFF.md` 第 3 节，用隔离的测试数据库）
- [ ] 普通用户：站点菜单里显示"渠道 N"和备注，看不到真实名字；价格表里有新站点
- [ ] 管理员：后台概览有新渠道余额卡片，价格表有新的一列，能填 Key、能保存价格
- [ ] **不在本地调用付费生图**。真实生图要上线后由你自己用小额测试

### 7. 上线后

- [ ] 在管理后台填新站点的 API Key、核对价格
- [ ] 你自己用每个新模型生成一张，确认能扣费、能出图、失败能退款
- [ ] 更新 `HANDOFF.md` 的渠道列表和近期变更

## 二、给已有站点加模型

- [ ] `xxx-api.js`：模型加进 `*_SITE_MODELS` 和 `*_IMAGE_MODELS` / `*_TEXT_MODELS`。如果请求参数特殊，在 `*ImageRequestSpec` 和 `*ImagePrice` 里处理
- [ ] 土豆的模型目前写死在两处：`account/channels.js` 的 `CHANNELS`，和打包文件里的 `TUDOU_SITE_MODELS` / `TUDOU_IMAGE_MODELS`
- [ ] `display-model-names.js`：`DISPLAY_NAME_MAP` 加上显示名，文字模型还要在 `DISPLAY_ICON_MAP` 加图标
- [ ] `account/catalog.js`：加价格行
- [ ] `deploy/seed-prices.mjs`：加初始售价。线上价格以后台填的为准，这个文件只是初始值
- [ ] `canvas-price-table.js`：有分档（质量、官方/固定）的模型要加对应行
- [ ] 只给管理员用的模型：加进 `account/relay.js` 的 `ADMIN_ONLY_MODELS`
- [ ] 打包文件：搜一个同类模型（比如 `gpt-image-2.5`）看它在哪些地方被单独判断（比例、质量选项、参考图），新模型有同样需求时照着加
- [ ] 换 `?v=`，`npm test`，本地预览看模型菜单和价格表

## 三、下架站点

参考移除 Soon 的做法（PR 134、`tests/soon-removed.test.mjs`）：
- 以上所有地方都要删干净，服务器要拒绝向它扣费
- 用户保存的旧设置和旧项目要自动切换到别的站点
- 数据库里的旧记录先保留，要清理必须先问用户
